# Final test cases

Run `npm test` for the entire regression suite and `npm run test:coverage` for the engine coverage gate. The table points to the focused tests; earlier batch tests remain part of both commands.

| Case                       | Input or option                                                             | Expected observation                                                                                                                               | Test                                                                    |
| -------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Single process             | P1 arrives at 0, burst 7                                                    | All five schedulers finish at 7 with zero wait and response; the Gantt has one merged segment                                                      | `tests/engine/finalCases.test.js`                                       |
| Identical values           | Four processes arrive at 0 with burst 3, priority 1                         | Every scheduler orders P1 through P4 when RR quantum is 3                                                                                          | `tests/engine/finalCases.test.js`                                       |
| Huge arrival gap           | P1 runs 0–2; P2 arrives at 1,000,000                                        | Every scheduler inserts `IDLE` from 2 to 1,000,000; P2 finishes at 1,000,001                                                                       | `tests/engine/finalCases.test.js`                                       |
| 120 processes              | Arrivals in groups of four; bursts cycle 1–5; priorities cycle 1–7          | All six comparison timelines complete 120 processes and 360 units of useful work without gaps or overlaps; under the generous 15-second test guard | `tests/engine/finalCases.test.js`                                       |
| Invalid input              | Empty set, zero burst, negative arrival, duplicate PID, fractional priority | Validation fails and comparison throws `RangeError`                                                                                                | `tests/engine/finalCases.test.js`                                       |
| Scheduler invariants       | 500 deterministic workloads per algorithm, including preemptive Priority    | Execution equals burst, metrics identities hold, and Gantt intervals do not overlap                                                                | `tests/engine/invariants.test.js`                                       |
| Selector boundaries        | Exact CV and spread thresholds                                              | First matching rule and explanation use the computed values                                                                                        | `tests/engine/selectorRules.test.js`                                    |
| Evaluation reproducibility | 50 generated workloads with seed 2026                                       | Same workloads and tuned summary on repeated runs                                                                                                  | `tests/engine/workloadGenerator.test.js`, `tests/engine/tuning.test.js` |

The performance assertion is a loose regression guard for this synthetic input, not a throughput guarantee for every browser or arbitrary burst size.
